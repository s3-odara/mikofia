# Mikofia Project Guidelines

## Code Comments

- Write comments in English
- Use comments with appropriate frequency and volume
- Comment on:
  - Complex logic that isn't immediately obvious
  - Public APIs and struct definitions
  - Non-trivial algorithms or validation logic
  - Business logic decisions
- Avoid:
  - Obvious comments that just repeat the code
  - Over-commenting simple operations
  - Outdated comments that don't match the implementation

## Code Style

- Follow standard Rust conventions
- Use descriptive variable and function names
- Keep functions focused and single-purpose
- Prefer functional programming style:
  - Use iterators and combinators (map, filter, flat_map, etc.) over explicit loops
  - Break down complex logic into small, composable functions
  - Return `Option` or `Result` instead of using mutable state when possible
  - Use pattern matching with guards for cleaner conditional logic
